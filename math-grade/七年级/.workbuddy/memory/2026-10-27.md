1. **把"套公式"改成"要判断"**：解方程（组）→ 换元 / 含参 / 增根无解；
   化简求值 → 从给定数里**选合适的值**（考取值限制），或给值反求 x。
2. **把一问改多问递进**：几何题从"一步得出"改成"证明 + 按比例算角"，
   统计题从"读图算频率"改成"补全频数 + 中位数所在组 + 达标判断"。
3. **把应用改方案设计**：买球打折 → 租车枚举整数解 + 最低租金；工程问题 → 两种方案比费用 + 双目标冲突。

## ⚠️ 本环境 Edge headless 截图彻底不可用（重要）
本次发现：**`msedge --headless` 只能截 `about:blank`**，任何真实页面都静默失败：
- `file:///…`（ASCII 路径、中文路径都试过）→ 无输出、exit 0、无 png
- `data:text/html,…` → 同上
- 本地 `http.server` + `http://127.0.0.1` → 同上
- 加 `--no-sandbox --disable-dev-shm-usage --allow-file-access-from-files --headless=old --enable-logging=stderr` 全部无效，**连一行日志都没有**
- `--dump-dom` 同样返回空

两个坑：
1. **Bash 工具沙箱不放行 GUI 程序**：在 Bash 里跑 msedge 一律静默 exit 0；换 PowerShell 才能启动（`about:blank` 那次成功就是 PowerShell 跑的）。
2. **PowerShell 命令文本里出现 `%E4%B8%83` 这类 percent-encoding 会被安全策略误判成 cmd 的 `%VAR%` 语法并直接拒执行**。要传中文路径：先用 `Join-Path` 拼好、`[System.Uri]` 转 URI 放进变量，再传变量。

**替代方案**：`check_struct.py` 程序化校验 —— HTMLParser 检查标签配对与最大嵌套、题号连续、分值三桶合计、每题 selfscore 与 data-score 一致、SVG 数值越界（含 NaN/Infinity）、关键答案文本抽查、题干长度体检。配合 `verify_up.py`（131 项数值断言）。
→ **代价：排版没做像素级核对**，只能靠 CSS 度量估算（paper 920px、padding 46px、16px 字号 ≈ 51 字/行；90~98 字题干 = 2 行，属正常）。

## 教训
- SVG 里给拼图加"尺寸标注"必须先判断**哪个方向是 a**：顶部长方形是 130×52（水平 a、竖直 b），我第一版把水平方向标成 b，直接删掉更稳。
- 角平分线图的标签/角弧布局：先用单位向量相加求平分线方向、再求两射线交点（不要手算坐标），本卷 E(280,50)/F(211,170) → G(176.3,110)，∠EGF 实测 90.00°。
- 角的弧若跨过平分线就会与平分线交叉，只能画**不跨越平分线的短弧**（跨度 ≤ 半角）。

## 17:00 补记：截图能力恢复 + 排版系统性修复

### 一、headless 浏览器终于能用了
之前 Edge 的 `--headless=new/old` 对任何真实页面都静默失败（exit 0、无 png）。
真正的可用内核是 **Playwright 自带的 chrome-headless-shell**：

```
$HOME/AppData/Local/ms-playwright/chromium_headless_shell-1234/chrome-headless-shell-win64/chrome-headless-shell.exe
  --headless --disable-gpu --no-sandbox --hide-scrollbars
  --force-device-scale-factor=1.4 --window-size=1120,10000
  --screenshot="<绝对路径>.png" "<file:/// URL>"
```
- **Bash 工具能直接跑它**（不是 GUI 程序，沙箱不拦），不需要 PowerShell。
- `--dump-dom` 也正常：可以注入探针脚本 → 写 `document.title` → `--dump-dom | grep 'PROBE|'` 读回判分结果。
- 中文路径用 URL 编码（`%E4%B8%83...`）在 Bash 里没问题。

### 二、像素级核对抓出的真问题（六个文件通病）
| 缺陷 | 根因 | 修法 |
|---|---|---|
| 分式整体下沉、分母悬到行外 | `.frac{vertical-align:-.42em}` | 改 `vertical-align:middle;top:-.08em;line-height:1.12` |
| 分式两侧括号太小、不包分式 | 括号是普通字号 | 加 `.paren{font-size:1.3em}`，用脚本找出"紧贴分式两侧的圆括号"自动包 |
| 方程组写成 `{ A，B }` 内联 | 当初图省事 | 新增 `.sys` 两行组件；左花括号用 **CSS mask + 内联 SVG 路径**（`::before`，`background:currentColor` 跟随字色） |
| 角弧只有一小截、像杂散短线 | **弧的终点不在圆周上**（半径写错，SVG 自动缩放圆心 → 弧漂移） | 终点必须严格 `vertex + r·(cosθ, sinθ)`；写审计脚本全量核验 |
| 直方图"?"柱正好画在答案刻度上 | 直接按答案画 | 改成明显不对刻度的值（32 / 18），"?"留在柱内 |

**关键教训（推翻旧结论）**：角弧**该跨满整个角**，即使被角平分线切过也没问题——
之前看到的"一小截"不是"跨度≤半角"的必然，而是**端点半径写错**。

### 四、踩过的坑
- **引号批替换不能扫全文**：`<style>` 里的 `font-family:"Times New Roman"` 被成对匹配到含中文注释的长段，整段 CSS 被改成中文引号 → 样式崩。必须**只在 `<body>` 到 `<script>` 之间、且只处理标签外的文字节点**，并排除含 `{};:<>` 的内容。发现后 `git checkout` 回滚重做。
- Python 里改 HTML 中文引号时，Bash 内联 `-c` 的引号转义极易被吃掉（`replace()` 只收到 1 个参数），**改用写脚本文件**。
- 校验脚本自己的误判：`<text>` 不是空元素、`</html>` 在 `<body` 切片后会成"多余闭合"，都要显式排除。
